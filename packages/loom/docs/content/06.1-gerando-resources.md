## O comando

```bash
go run . artisan loom:make-resource Car
```

Ele faz três coisas:

1. cria a pasta `app/loom/admin/car/` com os quatro arquivos padrão;
2. adiciona o import e o `&car.Resource{}` no `Resources(...)` do `AdminPanelProvider`;
3. avisa a URL do resource.

```
app/loom/admin/car/
├── resource.go   identidade: URL, tabela, nomes, ícone, menu
├── form.go       formulário de criar/editar
├── table.go      colunas, filtros e ordenação da listagem
└── pages.go      ganchos das páginas de listar, criar e editar
```

Reinicie o app e o resource aparece no menu.

## Gerando a partir do banco

Com `--generate` (ou `-g`), o comando lê as colunas da tabela e monta o formulário e a listagem sozinho, como o `--generate` do Filament:

```bash
go run . artisan migrate
go run . artisan loom:make-resource Car --generate
```

A tabela precisa existir, então rode a migration antes.

### Como cada coluna vira campo

| Coluna | Campo do formulário | Coluna da tabela |
|---|---|---|
| `varchar(n)`, `char` | `form.Text` com `Rules("max:n")` | `table.Text`, ordenável e buscável |
| nome com `email` | `form.Email` | `table.Text`, buscável |
| nome com `password` | `form.Password` com `Rules("min:8")` | não aparece |
| `text`, `json`, `jsonb` | `form.Textarea` | não aparece |
| `boolean` | `form.Toggle` (com `Default` quando houver) | `table.Boolean` e um filtro Sim/Não |
| `integer`, `bigint`, `numeric` | `form.Number` | `table.Text`, ordenável |
| `date` | `form.Date` | `table.DateTime` |
| `timestamp` | `form.Date` (comentado: só edita o dia) | `table.DateTime` |
| `bytea`, `blob` | `form.FileUpload(...).StoreAsBinary()` | `table.FileLink` |
| `uuid` e outros | `form.Text` | `table.Text` |

Também entram:

- **`.Required()`**: coluna `NOT NULL` sem valor padrão.
- **`.Nullable()`**: coluna que aceita `NULL`. Campo vazio vira `NULL`, e não `""`.
- **`.Unique()`**: coluna com índice único.
- **ID e timestamps**: `id`, `created_at`, `updated_at` e `deleted_at` ficam fora do formulário. `created_at` vira a última coluna da tabela e a ordenação padrão.
- **Chave primária**: se não for `id`, o `PrimaryKey()` é gerado.
- **Sem timestamps**: se a tabela não tiver `created_at`/`updated_at`, o `Timestamps()` é gerado retornando `false`.

Os rótulos saem do nome da coluna (`published_on` vira "Published on"). Traduza-os no `form.go` e no `table.go`.

## Opções

| Opção | Padrão | Descrição |
|---|---|---|
| `--generate`, `-g` | | Monta o formulário e a tabela a partir do banco. |
| `--table=carros` | plural em snake_case (`BlogPost` → `blog_posts`) | Tabela do banco. |
| `--slug=frota` | o nome da tabela com hífens | URL: `/admin/frota`. |
| `--label=Carros` | `Cars` | Nome no plural (menu e títulos). |
| `--singular=Carro` | `Car` | Nome no singular (botões e mensagens). |
| `--icon=truck` | `rectangle-stack` | Ícone do [Heroicons](icones). |
| `--group=Frota` | sem grupo | Grupo do menu. |
| `--no-register` | | Não mexe no provider. |
| `--force`, `-f` | | Sobrescreve arquivos que já existem. |

O plural automático segue regras do inglês. Para tabelas em português, use `--table`:

```bash
go run . artisan loom:make-resource Carro --table=carros --label=Carros --singular=Carro --icon=truck --generate
```

O nome do resource vira o nome do pacote Go: `BlogPost`, `blog_post` e `blog-post` geram `blogpost`. Palavras reservadas do Go, como `type` e `func`, são recusadas.

## Páginas e ganchos (pages.go)

No Filament, cada resource tem as páginas `ListCars`, `CreateCar` e `EditCar`. No Loom essas telas já vêm prontas, e o `pages.go` reúne os pontos onde você muda o comportamento delas. Todos os métodos são opcionais e vêm comentados: descomente o que precisar.

| Método | Página | Quando roda |
|---|---|---|
| `ModifyListQuery(ctx, q) Query` | Listar | Ao montar a consulta da listagem (escopos, joins, esconder linhas). |
| `BeforeCreate(ctx, data) error` | Criar | Depois da validação, antes do `INSERT`. Pode alterar `data`. |
| `AfterCreate(ctx, data) error` | Criar | Depois do `INSERT`. |
| `BeforeSave(ctx, id, data) error` | Editar | Depois da validação, antes do `UPDATE`. Pode alterar `data`. |
| `AfterSave(ctx, id, data) error` | Editar | Depois do `UPDATE`. |
| `BeforeDelete(ctx, ids) error` | Excluir | Antes de excluir um ou vários registros. |

### Exemplo

```go
package car

import (
	"strings"

	contractsdb "github.com/goravel/framework/contracts/database/db"

	"goravel/packages/loom"
)

// Lista só os carros ativos.
func (Resource) ModifyListQuery(ctx loom.Context, q contractsdb.Query) contractsdb.Query {
	return q.Where("is_active", true)
}

// Normaliza a placa e guarda quem cadastrou.
func (Resource) BeforeCreate(ctx loom.Context, data map[string]any) error {
	data["plate"] = strings.ToUpper(data["plate"].(string))
	data["created_by"] = ctx.User()["id"]
	return nil
}

// Impede excluir carros alugados.
func (Resource) BeforeDelete(ctx loom.Context, ids []any) error {
	rented, err := ctx.DB().Table("cars").WhereIn("id", ids).Where("status", "rented").Exists()
	if err != nil {
		return err
	}
	if rented {
		return loom.Halt("Não é possível excluir carros alugados.")
	}
	return nil
}
```

### Parando uma ação com loom.Halt

O retorno do gancho decide o que acontece:

- **`loom.Halt("mensagem")`**: cancela a ação e mostra a mensagem. Em criar e editar, o formulário volta preenchido com o aviso. Na exclusão, a listagem mostra o aviso.
- **Qualquer outro erro**: vira a página de erro 500, e o erro vai para o log.
- **`nil`**: a ação continua normalmente.

## Configurando o comando

O comando é registrado no `Boot` do `AdminPanelProvider`:

```go
loom.NewMakeResourceCommand(loom.MakeResourceConfig{
	Dir:      "app/loom/admin",                        // onde as pastas são criadas
	Provider: "app/providers/admin_panel_provider.go", // onde o resource é registrado ("" = não registra)
	Schema:   facades.Schema,                          // usado pelo --generate
}),
```
